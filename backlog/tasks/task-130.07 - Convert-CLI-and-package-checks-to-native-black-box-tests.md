## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The CLI checks mix public package execution, command-contract generation, documentation audits, repository registries, and local HTTP doubles. Convert check-cli-surface, check-command-contract, check-command-workflows, check-install-doc, and check-repos into typed black-box tests.

Keep package behavior black-box. Resolve and invoke the shipped bin entry from outside the checkout where the current check does so. Do not replace Commander parsing, filesystem effects, artifact order, or registry isolation with mocks.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 The five named legacy checks are replaced by typed native system tests grouped by CLI help and argv, command-contract artifacts, command workflows, install documentation, and repository registry behavior.
- [ ] #2 CLI tests resolve bin.archboard from package.json, invoke it from outside the checkout, and preserve no-argument help, every command topic, global routing, clean streams, usage exits, refusal exits, and import path resolution.
- [ ] #3 Command-contract tests preserve schema validation, held presentation, stdout and local-write ordering, private artifact rejection, exact generated bytes, twice-from-absent generation, and unchanged checkout status.
- [ ] #4 Install and repository tests use isolated temporary homes, checkouts, and registries and never read or write the real checkout registry or user configuration.
- [ ] #5 Subprocess failures report command, cwd, status, signal, stdout, and stderr; cleanup runs after assertion failure and waits for every owned child.
- [ ] #6 Every test source file is at most 500 lines and all fixtures, subprocess results, parsed JSON, and artifact records cross an explicit type or schema boundary.
- [ ] #7 Representative argv, artifact-order, generated-byte, installation, and registry-isolation regressions fail the native tests before the old scripts are deleted.
<!-- AC:END -->
