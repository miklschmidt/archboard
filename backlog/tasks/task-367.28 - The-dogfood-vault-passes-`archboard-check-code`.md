## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-367 #5 asks that the dogfood vault pass the code check. After TASK-367.27 corrected the boards, `./bin/dogfood check --code` still exits 1 with 31 warnings, so a task can never close on a clean check and a new warning drowns among the old ones. ADR 0046 says right work must be able to clear every warning, so each remaining warning is either a board that does not draw what the code does, or a check that calls something a dependency that is not one. About a third are uses of a constant, an error class in a catch or instanceof, or a type guard, which the check counts as call evidence. The rest are real calls that the Archboard server, Board viewer, Board rasterizer, Codex session, Voice coordinator, Agent workbench and Codex workhorse boards do not draw. The 367.27 group notes on TASK-367.27 explain each one.
<!-- SECTION:DESCRIPTION:END -->

Judgement 1, criterion #2. The rule as built is right, and the criterion can say it. Suggested wording: a use that runs none of a name's code never makes RELATIONSHIP_UNDRAWN or CALLER_UNDRAWN on its own. Examples are a constant read, a name passed on, and an error class caught or tested. Such a use stays call evidence, so it still supports an anchor and a relationship. A call or a construction still makes a dependency undrawn. The reasons: ADR 0046 lets an anchor cite "the value that it passes on". So a use as a value must stay evidence that supports a relationship. The evidence kind says what a use proves, and "undrawn" says what the board must draw. These are two questions, and the rule keeps them apart. I ran the source before the task (d5f171a78) and the source at HEAD over two vaults: the vault before 266f05595 and the current vault. Every finding other than RELATIONSHIP_UNDRAWN and CALLER_UNDRAWN is the same, line by line, evidence included. RELATIONSHIP_BACKWARDS, RELATIONSHIP_UNSUPPORTED, ANCHOR_MISMATCH, EXPOSED_UNUSED and the skips did not move. On the boards before 266f05595, the undrawn warnings went from 31 to 25. The environment join reads only references "via environment". Those never carry the mark, so the infrastructure joins cannot move.

The cost of "a name passed on". I removed every relationship and flow from a copy of the dogfood vault. That copy has 246 undrawn findings without the rule and 205 with it. For 28 pairs of parts, a name passed as an argument was the only evidence, and these pairs lost their warning. 21 of the 28 are real registrations. 18 are the command contracts of the command table in run.ts. 3 are write routes that semantic-board-routes.ts mounts, as in app.post(..., asyncEndpoint(createRoute)). The other 7 are constants. On Flask, I bound 20 parts to src/flask with no relationships. 15 findings of 19 stay. The 8 argument-only pairs are each an isinstance test, a TypeVar bound or a t.cast, and it is right to drop them. 4 more real pairs are hidden inside findings that stay, because Flask keeps a value to run it later. Examples are app_ctx_globals_class = _AppCtxGlobals, json_provider_class = DefaultJSONProvider, json_module = json, and a function in a list. Under ADR 0046, a registered handler that the board leaves out meets all three warning conditions. But syntax cannot tell a handler passed on from a constant passed on. CAMERA_MOTION_ATTRIBUTE, warning 18, is a constant passed as an argument. No right work clears a warning to draw a constant. Recommended follow-up: code facts that say what a definition is (a function, a class or a value). With that fact, a function or a class passed on can count as running.
