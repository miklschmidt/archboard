## Prerequisites

- Linux (x64 or arm64) or macOS (Apple silicon). On Windows, use WSL 2.
- Git and a Node.js package manager: npm, pnpm, Yarn, or Bun.
- A Codex sign-in only if you want the agent dock, voice mode, narration, or video recordings. Modeling, checks, and diagram rendering work without it.
- Chromium or Chrome only for PNG exports and video recordings. SVG exports need no browser.

## Install the CLI

The npm package is `archboard` (also published as `@archboard/cli`). Choose your package manager:

<InstallCommands id="docs-install" then={["archboard --version"]} />

The package manager installs only the binary for your platform and puts `archboard` on your `PATH`.

## Set up a repository

Run `archboard init` inside the repository you want to map:

```bash
cd ~/Projects/payments-api
archboard init
```

<Steps>

1. **Installs the agent skills.** `archboard` reads and writes models. `archboard-pr` writes architecture summaries for pull requests. `archboard-plan` drives a proposal through `to-spec`, `to-tickets`, and `implement-spec`. `archboard-deepen` refactors shallow modules and wide interfaces using two advisor agents for design decisions. Skills install for Codex, and also for Claude Code when `claude` is on your `PATH`.
2. **Creates the vault.** Archboard creates `.archboard/vault` at the repository root and names the model after the repository directory.
3. **Registers the checkout.** The local browser UI lists the repository, and code bindings to this repository resolve to this checkout.
4. **Configures language servers.** In an interactive terminal, `archboard init` asks whether Claude Code or Codex should set up language servers. The agent displays its plan and waits for confirmation. In non-interactive mode, the JSON output includes a `next` prompt for your agent.

</Steps>

Commit the vault with your code so reviewers see architecture changes in the same diff as code changes:

```bash
git add .archboard
git commit -m "docs(architecture): add the Archboard vault"
```

<Aside type="note" title="No `CLAUDE.md` or `AGENTS.md` entry">
	`archboard init` does not edit `CLAUDE.md` or `AGENTS.md`. CLI commands locate the vault from the
	current repository automatically, just like Git locates `.git`. If an earlier version added a block
	between `<!-- archboard:begin -->` and `<!-- archboard:end -->`, `init` removes it.
</Aside>

## Set up the language servers

A language server resolves symbol definitions across your codebase. With a language server configured, `archboard check code` produces resolved evidence that can raise warnings. Without one, name-only matches stay at information severity.

<Steps>

1. Identify the languages used in the repository.
2. Install a language server for each language that lacks built-in support. TypeScript {reference.facts.nativeTypescript} and later work without a separate server.
3. Register each server in the checkout:

   ```bash
   archboard repo language-server python pyright-langserver --arg=--stdio
   ```

4. Commit `.archboard/language-servers.json` with the vault so every developer machine and CI job uses the same configuration. Each machine still needs the language server binaries installed. See [Run checks as a gate](../gate/#in-ci) for CI setup.

</Steps>

In the browser UI, the Measures dialog lists any language from the last code check that lacks a server, along with the server it needs. Click **Fix with Codex** to ask the checkout's agent to configure it using the same steps as `archboard init`.

<Aside type="caution" title="Language servers execute repository code">
	Inspect `.archboard/language-servers.json` before running `archboard check code` in an untrusted
	repository. Tools such as `pyright`, `rust-analyzer`, and `gopls` execute code from the checkout,
	just as they do in an editor.
</Aside>

## Start the server

Any command that needs the local server starts it automatically. To start it manually and check its status, run:

```bash
archboard start
archboard status
```

The release server listens on <code>{`http://archboard.localhost:${reference.facts.releasePort}`}</code>. Chrome and Firefox route `*.localhost` domains to your local machine without extra setup. The CLI connects to <code>127.0.0.1:{reference.facts.releasePort}</code>. Set `ARCHBOARD_NO_AUTOSTART=1` to disable automatic startup.

<Aside type="caution" title="Keep the server on loopback">
	The server has no authentication. Do not expose its port outside your local machine.
</Aside>

## Verify the installation

```bash
archboard model read
archboard check
```

`archboard model read` prints the model as JSON. A new vault starts as an empty planning model with no current state yet, and `archboard check` exits `0`.

## Find the vault from another directory

CLI commands search upward from the working directory for `.archboard/vault`, just like Git finds `.git`. Pass `-C <dir>` to target another directory:

```bash
archboard -C ~/Projects/payments-api model read
```

If no vault exists at the repository root, the command exits with <Exit command="model read" refusal="VAULT_NOT_FOUND" /> and prints setup instructions. If another registered vault binds to this repository, the error lists its path so you can pass it to `-C`.

## Update and uninstall

Re-run the install command to update, then restart the server so it loads the new version. Until you restart, commands warn about the version mismatch.

```bash
npm install --global archboard@latest
archboard restart
```

There is no built-in uninstall command. To remove Archboard, stop the server and uninstall the package:

```bash
archboard stop
npm uninstall --global archboard
```

Then delete the skill directories (such as `~/.agents/skills/archboard`, `~/.agents/skills/archboard-pr`, `~/.agents/skills/archboard-plan`, and `~/.agents/skills/archboard-deepen`) and the local state directory. The state directory holds your Codex sign-in, checkout registry, and logs: `~/.local/state/archboard` on Linux, or `~/Library/Application Support/archboard` on macOS. Your vaults stay inside their repositories and are not affected.

See [`INSTALL.md`](https://github.com/miklschmidt/archboard/blob/main/INSTALL.md) for building from source, Nix, full language server setup, video recording dependencies, machine state, and macOS details.
