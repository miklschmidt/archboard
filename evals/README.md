# Evaluate the canonical consumer skill

The active suite contains eight canonical scenarios, eight authored fixtures, and fourteen coverage parts.
Run `bun run eval:skill check` for deterministic suite checks.
This command reads real temporary fixture files through the public architecture reader.
It does not call a model.

Each fixture supplies canonical authored inputs, shared policy, and an optional repository registration.
Fresh scenarios never use legacy board writers, fixed levels, or retained talk fixtures.
The isolated harness installs the current skill into a disposable local author environment.
It retains the original prompts, events, outcomes, audit evidence, and captures for later grading.
A fixture snapshot includes the raw canonical reading and derived semantic content for existing outcome comparisons.
That derived record is evaluation evidence and cannot author a vault.

The scenarios cover initial planning, bound modules, independent proposals, recursive interfaces, flows, walkthroughs, exact history, reproducible exports, and local inspection.
Captures use `model rasterize` through the existing local renderer and rasterizer.
Their evidence records model identity, state, complete revision, dimensions, fonts, and the SVG digest.
The harness supplies the captures to graders.

Existing evaluation records and frozen skill baselines remain historical evidence.
Their legacy receipts and recorded talks remain decodable for that purpose.
They are not a valid baseline for new canonical workflow scores.
Run a new canonical baseline before comparing quality, cost, or authoring time.
No model evaluation is part of deterministic validation.
