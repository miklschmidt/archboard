# Align the proposal and implementation

Read the proposal and diff at their exact architecture and source revisions.
Use the parent skill's comparison, footprint, and code inspection commands.
Account for every affected subject:

- Implemented as proposed: Preserve IDs and attach actual bindings and anchors.
- Proposed but unimplemented: Keep it proposed, or record an authorized removal.
- Implemented but undescribed: Add the actual architectural change to the proposal.

Resolve design differences within existing authorization.
If a decision exceeds it, show the owner the source difference and required choice.
Continue independent work while awaiting that choice. Routine factual corrections need no repeated permission.
For standing or changed predecessors, follow the consumer reconciliation and settlement recipe across the affected family.

If the design document changed, read its diff from the referenced commit.
Update the affected meaning and document reference in one edit, preserving unrelated proposals and baselines.
A larger design can retain planned subjects while supporting a narrower implementation.
Use a dependent proposal only when its complete predecessor fits that implementation.
Use scope and focus to narrow pictures, never delete planned subjects to create a smaller picture.

Finish when the proposal matches the authorized change, document references identify its source, and affected standing is explicit.
