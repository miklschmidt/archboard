# Semantic renderer fork comparison

Date: 2026-09-11

## Scope and revisions

This compares source reuse against [ADR 0023](../adr/0023-semantic-boards-own-meaning-renderers-own-presentation.md):
agents author meaning and presentation intent, while the renderer owns all coordinates, sizing,
styling, and routing. A chosen fork inherits every grammar that candidate currently supports.
Visual quality is deliberately not ranked from source.

- PR Lens: `coldteadotai/pr-lens` main at [`0993b4d`](https://github.com/coldteadotai/pr-lens/tree/0993b4dec8ae73f5e000370e6a758cdd8aa2bfd0),
  including renderer `0.2.4` and schema `0.2.1`.
- Archify: main at [`c1443b3`](https://github.com/tt-a1i/archify/tree/c1443b31b496eebf4a68bf83151816c955ddb796),
  identified as `2.17.0-dev.1`; the latest stable release is
  [`v2.16.0`](https://github.com/tt-a1i/archify/releases/tag/v2.16.0) at `c826e6c`.

## What Archify still asks the author to lay out

| Grammar      | Existing required composition; optional escape hatches                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Architecture | Every component needs absolute `pos`, or grid `row`/`col`; optional size, viewBox, sides, route, via points, and label coordinates expose more geometry. ## Fork implications

**PR Lens's strongest limitation:** its closed, PR-specific `GraphDoc` requires repository base/head
provenance, lanes, and deltas and has no recursive node containment; its two renderers are reusable,
but the semantic board schema and required viewer are new product work
([document schema](https://github.com/coldteadotai/pr-lens/blob/0993b4dec8ae73f5e000370e6a758cdd8aa2bfd0/packages/schema/src/graph.ts#L371-L427)).
It is the cleaner base if preserving the renderer-owned boundary matters more than grammar breadth.

**Archify's strongest limitation:** authored placement coordinates occur in all five grammars, and
four also expose route controls, directly violating ADR 0023. Retaining five grammars means adding a semantic-to-layout compiler per
grammar and making current geometry keys renderer-internal. Its strongest reuse is instead the five
visual grammars, validators, routing machinery, semantic DOM hooks, and complete reader shell.

The next interview can therefore choose on one real tradeoff: PR Lens starts closer to the desired
authoring contract with two grammars and little viewer reuse; Archify starts closer to the desired
reader and grammar surface but requires the larger layout-boundary rewrite. Neither currently
satisfies recursive containment or the agreed name / optional responsibility / description model.
